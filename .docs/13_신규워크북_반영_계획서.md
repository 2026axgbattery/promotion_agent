# 13. 신규 워크북(`data_sample.xlsx`) 반영 계획서

## 배경/동기
사용자가 실제 매달 업로드할 워크북 양식을 새 샘플(`data_sample.xlsx`)로 제공했고, 구조 분석 후 다음을 확인받았다:
- 백데이터 시트의 `Status`(Billing/Delivery)는 실제 운영에서는 전부 Billing만 온다.
- 백데이터의 DC 관련 컬럼(매출DC/판촉DC/LME연동DC/수금DC/특판DC/카포스DC/제품군DC 등)은 무시한다 — 대리점별 고정 DC(매출DC+성장DC)는 **총괄표**에서만 가져와 대리점 단위로만 반영한다(품목별 DC율 적용 불필요).
- 프로모션 기준 시트는 현재 줄글 초안이고, 최종본은 표로 제공될 예정이다(지금은 반영 대상 아님).
- 프로모션 지원액(10+1·대형제품·특화제품·기타·추가·그 외)도 전부 **총괄표**에 대리점 단위로 이미 계산되어 있으므로, 그 값을 그대로 사용한다.
- 백데이터는 지금 단계에서는 실질적으로 쓸 데이터가 없다(수량 파악 용도는 프로모션 기준표가 구조화된 이후에 다시 검토) — 이번 반영에서는 사용하지 않는다.
- **대리점 × 제품 단위 세부표는 삭제**한다 — 위 이유로 제품 단위 지원금액을 신뢰성 있게 산출할 방법이 없다. 이제 이 앱은 **대리점 단위 비교만** 제공한다.

## 범위
1. `app/workbook_ingest.py`: 기존 (백데이터+총괄표+프로모션+대형) 4시트 조합·배분 로직을 전부 걷어내고, **총괄표 시트 하나만으로 대리점 단위 결과표**를 만드는 로직으로 새로 작성한다.
   - 컬럼: 기준연월·대리점코드·대리점명·판매수량·매출액·전월매출·매출증감율(계산)·영업이익·영업이익율(계산)·DC율(매출DC+성장DC)·DC지원금액(계산)·프로모션지원금액(총괄표 "프로모션 합계" 그대로)·총지원금액·원가율(여전히 없음, NaN).
   - 지원유형별 내역(`applied_support`)은 총괄표의 매출DC/성장DC/10+1/대형제품/특화제품/기타/추가/그 외 컬럼을 그대로 롱포맷으로 편다(0원 제외).
   - `aggregate_by_store()`는 더 이상 필요 없다 — 총괄표 자체가 이미 대리점 단위 그레인이기 때문이다.
2. `app/db.py`: `sales_record` 스키마에서 제품 그레인 컬럼(제품군·제품코드·제품군판매수량합계)을 제거한다(그레인이 대리점 단위로 바뀜).
3. `app/streamlit_app.py`: "대리점 × 제품 단위 상세" 표를 제거하고, 대리점 단위 결과표 하나만 보여준다.
4. 테스트(`app/tests/test_workbook_ingest.py`, `test_ingest_to_db.py`, `test_streamlit_app.py`)를 새 구조에 맞게 다시 작성하고, 실제 자료 기반 통합 테스트는 `sample04.xlsx` 대신 `data_sample.xlsx`를 사용한다.

## 추가 반영 (사용자 확인)
- 지원유형별 지원금액 내역에 대리점명을 추가한다.
- 제품군(GB/AGM/대형/특화)별 판매수량·지원금액을 대리점 구분 없이 전사 합계로 보여준다. 대형·특화는 총괄표 컬럼 그대로라 정확하지만, "10+1"은 총괄표에 GB+AGM이 합산되어 있어 백데이터의 GB/AGM 판매수량 비중으로 추정 배분한다(추정치임을 명시).
- 분석 결과 화면 맨 위에 "이달 프로모션 시행 내용"을 보여준다. 프로모션 기준 시트가 아직 표가 아니라 줄글이므로, 이 시트의 텍스트를 그대로 읽어 보여준다(임의로 구조화·요약하지 않는다 — 최종본이 표로 오면 그때 정식 파싱으로 바꾼다).

## 완료 기준

- `pytest` 전체 통과.
- 기존 `app/data/promotion_history.duckdb`는 스키마 변경으로 삭제 후 재생성한다.
