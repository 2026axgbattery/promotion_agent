# 12. 업로드 구조 개편 계획서

## 배경/동기
현재 `app/streamlit_app.py` 화면에는 (1) 월 마감 워크북 업로드(주 경로), (2) "DB 상태(참고)" 패널, (3) 레거시 "실적 파일 + 프로모션 기준 마스터" 2파일 업로드 패널이 함께 있다. 사용자는 프로모션 지원금 계산에 필요한 **프로모션 기준표**(산식유형·문턱값·지원단가 등)까지 월 마감 워크북 안의 시트 하나로 통합해서 올리길 원하며, 그에 맞춰 화면도 단순화(DB 상태 참고·레거시 패널 제거)하길 원한다.

## 범위
1. `app/streamlit_app.py`: "DB 상태(참고)" expander와 레거시 2파일 업로드 expander를 제거하고, 화면을 "월 마감 워크북 업로드 → 결과 확인 → 저장" 단일 흐름으로 단순화한다. 더 이상 쓰이지 않는 `app/parsing.py`(`list_sheet_names`, `read_table`)·`app/validation.py`(`validate_uploads`, `UploadValidationResult`) import를 정리한다(파일 자체는 남겨둔다 — 레거시 코드 보존 여부는 별도 판단).
2. `app/workbook_ingest.py`: 사용자가 새로 제공할 워크북 샘플(프로모션 기준표 시트가 포함된 새 양식)을 받아, 그 시트에서 산식유형·문턱값·지원단가 등 프로모션 기준 마스터 데이터를 파싱하는 로직을 추가한다. **이 부분은 실제 시트 구조를 확인한 뒤 반영**한다(현재는 사용자가 파일을 준비 중).

## 방법
- 1번(화면 정리)은 기존 계산 로직에 영향이 없으므로 즉시 진행한다.
- 2번(프로모션 기준표 파싱)은 사용자가 업로드할 새 샘플 워크북을 받아, 시트명·헤더 구조를 확인한 뒤 `extract_프로모션기준표()` 같은 함수를 추가하고 `build_sales_like_table()`의 지원금액 계산 로직(현재는 대리점 단위로 이미 계산된 지원금액을 제품 단위로 배분만 하는 방식)을 프로모션 기준표 기반 자동 판정·계산으로 전환할지 여부를 다시 검토한다.

## 완료 기준
- 화면에 "월 마감 워크북 업로드" 흐름만 남고 DB 상태 참고·레거시 2파일 업로드 패널이 사라진다.
- 기존 테스트(`pytest`)가 모두 통과한다.
- 새 워크북 샘플 반영 후, 프로모션 기준표 시트를 읽어 지원금액 계산에 사용할 수 있다(2번 완료 시점은 샘플 파일 수령 이후).
