# 20. "26년 8월 DC 총괄표.xlsx" 교차검증 및 구간별단가 그룹합산 수정

## 배경/동기
`19_최종백데이터_전환_계획서.md`에서 도입한 "역산 검증"(매출액-매출원가-영업이익 vs 계산된
총지원금액)이 대형 대리점 6곳(영창비앤티·서부상사·계양로케트·엠씨비앤티·오투오플래닛·
로켓트플러스)에서 유난히 크게 어긋났다. 사용자가 팀 자체적으로 작성하는 공식 집계 자료
"26년 8월 DC 총괄표.xlsx"(단위: 천원)를 제공해, 이 6곳을 그 자료와 직접 대조했다.

## 확인된 사실
1. **매출DC·성장DC·연동형(Level up) 계산은 이미 정확했다.** 예: 2101090(영창비앤티) 매출DC
   207,457,670원 vs 총괄표 207,457,700원, 성장DC 62,237,301원 vs 62,237,301원(완전 일치).
   연동형은 대상 품목 지원(26,091,000원) + 트리거(AGM) 자체지원(44,480,000원) =
   70,571,000원이 총괄표의 "프로모션" 항목과 정확히 일치 — 트리거제품군 자체지원 메커니즘이
   맞다는 것을 실측으로 확인했다.
2. **실제 버그 발견**: "구간별단가-절대수량"(예: "특화")을 제품코드 단위로 개별 판정하고
   있었는데, 실제로는 **같은 프로모션명 그룹에 속한 모든 제품코드의 판매수량을 대리점
   단위로 합산한 값**으로 구간을 판정해야 한다(AGM Level up의 트리거 판정과 같은 원리이자,
   CLAUDE.md의 핵심 도메인 규칙 "같은 대리점·같은 제품군의 여러 행은 합산해서만 프로모션
   대상 여부를 판정한다"와 정확히 같은 얘기). `app/workbook_ingest.py`의 계산 루프와
   `_build_threshold_proximity`를 그룹 합산 기준으로 고쳤다. 6개 대리점 전부 대조해
   5곳은 총괄표와 완전히 일치, 1곳(2101435)만 8만원짜리 작은 예외로 남았다(총괄표 쪽
   수기 보정일 가능성).
3. **데이터 누락 발견**: 6개 대리점 전부 "대형" 지원액이 정확히 "그 대리점의 GB67018
   판매수량 × 3,000원"만큼 총괄표보다 작았다. GB67018(PCC06954)이 GB73010/73011/250L/250R처럼
   "특화+대형" 동시 적용 품목인데 "대형" 행이 빠져 있었던 것 — `업로드 실적(8월).xlsx`의
   "프로모션 기준" 시트 맨 끝(69행)에 대당 3,000원짜리 "대형" 행을 추가했다(기존 병합 셀
   레이아웃을 건드리지 않도록 중간 삽입 대신 표 끝에 추가).
4. **"역산 검증" 기능 자체를 MVP에서 제거했다** — 계산이 정확하다는 게 총괄표로 확인된
   이상, 부가세 등 다른 고정비가 섞여 신뢰도가 낮은 이 방식을 계속 노출할 이유가 없다는
   사용자 판단(사용자 확인). `IngestResult.sales_like`의 `역산총지원금액`·`역산차이` 컬럼,
   화면의 "역산 검증" 섹션, DB 스키마의 해당 컬럼을 모두 제거했다.

## 완료 기준
- 6개 대리점의 매출DC·성장DC·대형·특화·연동형(대상+트리거) 지원액이 총괄표와 일치(대형·
  연동형은 완전 일치, 특화는 5/6 완전 일치·1곳만 8만원 오차, GB67018 대형 행 추가 후
  대형도 전 매장 완전 일치).
- `pytest` 전체 통과(그룹합산을 검증하는 신규 테스트 포함, 역산 검증 관련 테스트는 삭제).
- 화면에서 "역산 검증" 섹션이 보이지 않는다.
