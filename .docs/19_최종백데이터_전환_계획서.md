# 19. 최종 백데이터(DC율/프로모션 기준/DATA) 전환 계획서

## 배경/동기
사용자가 "궁극적 목표는 프로모션 기준이 바뀌어도 코드 수정 없이 바로 인식할 수 있는 최종 백데이터 양식을 만드는 것"이라고 확인했다. 지금까지 `.docs/13`·`15`·`16`번에서 만든 총괄표 기반 경로는 앞으로 쓰지 않기로 했고, `.docs/17`번의 DC율/프로모션 기준/DATA 경로 하나로 완전히 수렴한다.

## 범위
1. **산식유형 명시 컬럼 도입**: 지금은 `_infer_규칙_v2`가 "대형"/"특화"/"Level up"이라는 프로모션명 **문자열 자체**로 산식을 추측한다 — 다음 달 이름이 바뀌면 계산이 멈춘다. `업로드 실적(8월).xlsx`의 "프로모션 기준" 시트에 **"산식유형"**(무상증정/품목별고정단가/구간별단가-절대수량/연동형 중 하나) 컬럼과, 연동형일 때 트리거가 되는 제품군을 적는 **"트리거제품군"** 컬럼을 추가한다. 프로모션명은 화면 표시용 자유 텍스트로만 남긴다.
2. **AGM Lv(연동형) 문턱값 근접도**: 대리점별 AGM 전체 판매수량(DATA에서 제품구분1='AGM' 전체 합)과 그 대리점의 Lv.1~3 문턱값을 대조해 "다음 Lv까지 몇 대 남았는지"를 보여준다. 같은 방식을 구간별단가(특화 등)에도 적용한다.
3. ~~**역산 검증**: `매출액 − 매출원가 − 영업이익`으로 나온 값과 우리가 계산한 총지원금액을 나란히 보여준다(상관 0.997, R² 0.994 확인됨 — 두 값이 크게 어긋나면 데이터나 산식 오류 신호).~~ **(삭제, 사용자 확인)** 실제로 만들어 써보니 이 방식은 부가세 등 다른 고정비가 섞여 있어 대형·맞춤단가 대리점일수록 오차가 컸다. "26년 8월 DC 총괄표.xlsx"(공식 집계 자료)로 직접 대조해보니 계산 자체는 정확했고(대형 대리점 6곳 검증, 오차 0~0.1% 수준), 오히려 이 역산 방식이 못 미더운 것으로 판명나 MVP에서 뺐다. 검증이 필요하면 이런 공식 총괄표류 자료와 직접 대조하는 편이 낫다.
4. **총괄표 경로 완전 삭제**: `extract_총괄표`·`extract_제품표`·`extract_backdata_quantities`·구 `_compute_프로모션_규칙기반`·구 `_build_product_group_support`·구 `threshold_proximity` 등 총괄표 전용 코드를 전부 지운다. `build_sales_like_table`은 DC율/프로모션 기준/DATA 형식만 인식한다.
5. **레거시 정리**: `app/schema.py`·`app/validation.py`·`app/parsing.py`(레거시 2파일 업로드용, 이미 화면에서 제거됨)와 관련 테스트를 삭제한다. `db.py`의 `promotion_master`·`store_agm_baseline` 테이블과 시드 적재(`load_seed_data`)도 제거한다 — 실제로 쓰이지 않는 죽은 스키마였다.
6. **제품군별 요약 재설계**: 기존 "GB/AGM/대형/특화"는 제품 타입 축과 프로모션 종류 축이 섞여 있었다. 이제 **제품구분1(GB/AGM/PT)** 단일 축으로 정리한다 — 프로모션 종류별 내역은 이미 "지원유형별 지원금액 내역"에 있으므로 중복이 아니다.

## 완료 기준
- `업로드 실적(8월).xlsx`(산식유형 컬럼 추가된 버전)를 올리면 기존과 동일한 계산 결과가 나오되, 산식유형 컬럼 기반으로 계산된다(프로모션명이 바뀌어도 계산이 유지되는지 별도 케이스로 검증).
- AGM Lv 문턱값 근접도 값이 화면에 나온다.
- 총괄표 기반 워크북(`data_sample.xlsx`, `dummy_실적워크북.xlsx`)은 더 이상 지원하지 않는다 — 업로드 시 "DC율 시트가 없습니다" 같은 명확한 오류를 낸다(회귀가 아니라 의도된 축소).
- `pytest` 전체 통과(총괄표 관련 테스트는 삭제, 새 케이스로 대체).
