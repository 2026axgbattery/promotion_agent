# DBMS 도입 및 기준연월 탐색 UI 반영 계획서

## 배경/동기
`02_PRD.md`는 현재 "세션 간 데이터 영속 저장을 제공하지 않는다(stateless 웹앱 전제)"를 비목표로 명시하고, 7절 데이터 모델도 "세 테이블 모두 세션 내 메모리(pandas DataFrame)에만 존재하며, 업로드가 끝나면 세션 종료 시 폐기된다"고 규정하고 있다. 그러나 사용자가 확인한 실제 필요는 다르다: 예를 들어 2027년 2월 시점에 2026년 10월에 시행했던 프로모션의 효과를 다시 조회할 수 있어야 한다. 즉 분석 결과(대리점×제품 실적, 매칭된 프로모션, 지원금액, 영업이익율 등)를 **기준연월별로 누적 저장**하고 이후 시점에 과거 연월을 선택해 다시 불러볼 수 있어야 하므로, 세션 종료 시 데이터가 사라지는 stateless 구조로는 이 요구를 충족할 수 없다. 따라서 "DBMS 불필요"라는 기존 전제를 "과거 프로모션 실적·효과를 조회하기 위한 DBMS(영속 저장소)가 필요하다"로 정정해야 한다.

또한 `output/분석결과화면.html`에는 우측 상단에 기준연월이 `2026-08`로 고정 표시되어 있을 뿐, 클릭해서 다른 연월(과거 시점)로 전환하는 UI가 없다. 이 계획서는 문서(PRD)와 화면(HTML) 양쪽에 "여러 기준연월의 분석 결과를 저장하고, 화면에서 연월을 선택해 과거 시점 결과를 다시 조회하는" 기능을 반영하기 위한 작업 범위를 정의한다.

## 범위
- `02_PRD.md` 수정
  - 3절 비목표: "세션 간 데이터 영속 저장을 제공하지 않는다" 문구 삭제/정정하고, 대신 "기준연월별 분석 결과를 DBMS에 누적 저장해 과거 시점 조회를 지원한다"를 목표로 전환
  - 5절 기능 목록·6절 상세 기능 요구사항에 "기준연월 선택/과거 이력 조회" 기능 신설
  - 7절 데이터 모델: 세션 메모리 전제를 DBMS 영속 저장 전제로 수정, 저장 대상(어떤 테이블을 어떤 키로 누적 저장하는지) 명시
  - 8절 엣지 케이스에 "조회하려는 기준연월에 저장된 분석 결과가 없음" 케이스 추가
  - 관련해 `02_프로모션효과분석_기획서.md`에 stateless 관련 서술이 있는지 확인 후 있으면 함께 정정
- `output/분석결과화면.html` 수정
  - 우측 상단 "기준연월" select-pill을 클릭 가능한 드롭다운으로 변경, 과거 여러 연월(예: 2026-08, 2026-10, 2027-02) 목록에서 선택 가능하게 함
  - 연월을 바꾸면 이번 달 시행 프로모션 카드, KPI, 효과 평가, 대리점×제품 결과 표, 편차 비교가 해당 연월의 데이터로 갱신되는 목업 로직(JS 데이터셋 분리 + 렌더링 재사용) 추가
  - design.md 토큰(`--color-*`, `--radius-*`, `--space-*`) 그대로 사용, 임의 색상/간격 추가 금지

## 방법
- PRD는 기존 6개 섹션 구조를 유지한 채 필요한 절만 국소 수정(전면 재작성 아님)
- HTML은 기존 `STORES` 객체 패턴처럼 연월별 데이터셋 객체(`PERIODS`)를 추가하고, 연월 변경 시 전체 렌더 함수를 다시 호출하는 방식으로 구현(새 프레임워크 도입 없이 기존 vanilla JS 패턴 유지)
- 과거 연월 데이터는 계산식 시연용 가상 값으로 구성하고(기존 화면과 동일한 전제), footer 주석에 "과거 연월 데이터도 실제 값이 아닌 시연용 가상 값"임을 명시

## 완료 기준
- `02_PRD.md`에서 "DBMS 불필요/세션 간 미저장" 전제가 "DBMS로 기준연월별 이력을 누적 저장하고 과거 시점 조회를 지원" 전제로 정정되어 있다.
- `output/분석결과화면.html`에서 우측 상단 기준연월을 클릭하면 드롭다운이 열리고, 다른 연월(과거 포함)을 선택하면 화면의 프로모션 카드·KPI·결과 표가 해당 연월 데이터로 바뀐다.
- 두 산출물 모두 design.md 토큰만 사용했는지, 기존 화면의 다른 기능(대리점 그룹 조회, 편차 비교 등)이 깨지지 않았는지 확인한다.
