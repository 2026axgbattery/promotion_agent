# 21. 업로드 로딩 UI · 자동 이동 · 분석 결과 대시보드 개편 계획서

## 배경/동기
사용자 피드백(첨부 참고 이미지: DashLite 투자 대시보드 스타일):
1. 실적 파일 업로드 후 분석이 끝날 때까지 아무 표시가 없어 멈춘 것처럼 보인다 — 스피너·스켈레톤 필요.
2. 업로드가 끝나면 "분석 결과" 탭을 직접 누르지 않아도 결과 화면으로 넘어가야 한다.
3. 분석 결과 화면이 엑셀 시트를 그대로 옮긴 줄글·표 위주라 한눈에 안 들어온다 — 카드형 대시보드로
   바꾸고, 차트가 필요한 곳은 스크롤해서 화면에 들어올 때 그래프가 차오르는 식의 인터랙티브 UI로.

## 범위
1. **업로드 로딩 UI**: `st.status`(단계별 진행 문구) + `st.progress` + 결과 화면 모양의 `st.skeleton`
   자리표시. 진행 단계는 가짜가 아니라 `build_sales_like_table`의 실제 단계(시트 읽기 → DC 계산 →
   프로모션 계산 → 분석 정리)에서 콜백으로 받는다.
2. **자동 이동**: 분석이 끝나면 `st.switch_page`로 분석 결과 화면으로 바로 이동하고, 도착 시 토스트로
   알린다. 같은 파일·같은 기준연월을 이미 분석했다면 업로드 화면에 다시 와도 재분석·재이동하지 않는다
   (업로드 화면에 머물 수 있게).
3. **분석 결과 대시보드**: KPI 카드 → 지원유형별 비중 막대 · 프로모션 시행 내용 카드 → 대리점별
   지원금액 TOP10(DC/프로모션 분리 누적 막대) · 프로모션 효과 평가 → 문턱값 근접도 게이지 →
   영업이익율×매출증감율 산점도 · 대리점 그룹 카드 → 편차 원인 구분 → 프로모션 장단점 카드 →
   상세 데이터(엑셀형 표는 맨 아래 탭으로) → 저장.
   - 차트는 `st.html(..., unsafe_allow_javascript=True)`(iframe 아님 — 페이지 폰트·스크롤을 그대로
     씀)로 그리고, `IntersectionObserver`로 화면에 들어올 때 막대·게이지가 차오르고 숫자가 올라간다.
     `prefers-reduced-motion`이면 애니메이션 없이 바로 최종 상태를 보여준다.
   - `dataviz` 절차 준수: 식별색은 SEBANG Green `#0097A9`·Orange `#EB3300`만(검증 스크립트 PASS),
     단일 계열은 한 색, 텍스트는 텍스트 토큰, 막대 끝 4px 라운드·2px 간격, 막대별 호버/포커스 툴팁,
     2계열 이상은 범례, 모든 차트의 표 보기(상세 데이터 탭) 유지.
   - 업로드 데이터(대리점명 등)는 HTML에 넣을 때 전부 이스케이프하고, 툴팁은 `textContent`로만 채운다.
4. **사이드바**: 참고 이미지처럼 어두운 사이드바(Ink `#1F3742`) + 흰색 워드마크(design.md 1.3·5절).

## 완료 기준
- 업로드하면 스켈레톤·진행 단계가 보이고, 끝나면 자동으로 분석 결과 화면으로 넘어간다.
- 분석 결과 화면이 카드·차트 중심으로 바뀌고, 스크롤 시 차트가 애니메이션된다(헤드리스 브라우저
  스크린샷으로 직접 확인).
- `pytest` 전체 통과(화면 구조가 바뀐 부분은 테스트도 갱신).
