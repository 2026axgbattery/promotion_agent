# 18. 남은 개발 항목 및 고도화 제안

`.docs/02_PRD.md`를 기준으로, 지금까지 구현된 것(`app/`)과 대조해 무엇이 남았고 무엇을 더 다듬을 수 있는지 정리한다. PRD의 MVP/최종 결과물 구분과 무관하게, 실제로는 최종 결과물 항목 상당수가 이미 MVP 단계에서 구현되어 있다 — 이 문서가 그 실제 현황을 보여준다.

## 1. PRD 5절 "MVP" 대비 구현 현황

| 기능 | PRD 정의 | 구현 현황 |
|---|---|---|
| 실적 파일 업로드 | 대리점×제품 단위 실적 엑셀 업로드 | ✅ 두 가지 실제 워크북 형식을 자동 인식: (1) 총괄표/백데이터/제품표 구조, (2) DC율/프로모션 기준/DATA 구조(`.docs/13`·`17`) |
| 프로모션 기준 마스터 업로드 | 별도 엑셀로 프로모션 조건 업로드 | 🟡 별도 파일이 아니라 워크북 안의 "프로모션 기준" 시트에서 직접 읽는다. 구조화된 표 형식이면 자동 계산하고, 아직 줄글이면 원문만 보여준다(계산은 안 함) |
| DC율 반영 매출 확인 | 대리점별 DC율·매출액 분리 표시 | ✅ 완료. DC율 경로(신규)에서는 제품별 "DC율 미적용" 여부까지 반영해 (대리점,제품) 단위로 정밀 계산 |
| 제품군 합산 판정 | 같은 대리점·제품군의 판매수량을 합쳐 문턱값 판정 | 🟡 부분 구현. 무상증정(10+1)의 문턱값 근접도는 구현됨. 다만 "여러 제품을 묶어 하나의 제품군 합계로 판정"하는 원안 그대로의 사례는 아직 실제 데이터에 없었다(실제로는 제품코드 단위 또는 다른 제품군 연동으로 판정되는 사례만 확인됨) |
| 지원단가·지원금액 산출 | 산식유형별 계산 + 복수 매칭 시 합산 | ✅ 완료. 무상증정·품목별고정단가·구간별단가(절대수량)·연동형 4종 중 3.5종 구현(아래 2절 참고). 한 제품이 "특화+대형"에 동시 매칭되는 사례도 검증함 |
| 영업이익율·매출증감율 병렬 표시 | 두 지표를 나란히 표시 | 🟡 영업이익율은 완료. 매출증감율은 전월매출 데이터가 아직 없어 공란(사용자가 DC율 시트에 곧 추가할 예정 — `.docs/17` 4번) |
| 분석 결과 DB 저장 | 기준연월 키로 DuckDB 저장, 재분석 시 덮어쓰기 | ✅ 완료 |

## 2. 산식유형 4종 커버리지 (PRD 6.3.1)

| 산식유형 | 상태 | 비고 |
|---|---|---|
| 무상증정 (10+1) | ✅ | 11대당 1대분 차감, 문턱값 근접도 분석까지 구현 |
| 품목별고정단가 | ✅ | "대형" 프로모션(대당 고정 금액) |
| 구간별단가 — 절대수량 | ✅ | "특화" 프로모션(50/100/300대 구간별 단가) |
| 연동형 | ✅ | "AGM Level up" — AGM 판매수량이 대리점별 문턱값을 넘으면 지정 GB 품목 지원 |
| 구간별단가 — 대리점별 상대 | ⬜ 미구현 | PRD 원안은 "그 제품군 자체가" 대리점별 상대 문턱값으로 지원받는 경우를 상정했는데, 실제 확인된 사례(AGM Level up)는 이 역할을 "연동형"이 대신하고 있었다. AGM 자체가 상대 문턱값으로 직접 지원받는 사례가 나오면 그때 추가 구현 필요 |

## 3. PRD 5절 "최종 결과물" 대비 구현 현황

과제 등록 정보 기준으로는 전부 최종 결과물 단계였지만, 세션 중 사용자 요청으로 다음이 이미 MVP에 들어와 있다.

| 기능 | 구현 현황 |
|---|---|
| 편차 원인 구분 표시 (6.5) | ✅ 구현됨. 단, PRD 6.5.2가 정의한 "칩 UI + 최대 5개 제한 + 검색 패널"은 아니고, 단순 멀티셀렉트 + 표 + 총평 문구로 구현됨(아래 4절 참고) |
| 프로모션 효과성 평가 (6.6) | ✅ 구현됨(해당/미해당 그룹 비교, ROI 추정) |
| 대리점 그룹별 조회 (6.7) | ✅ 구현됨. 단, PRD가 정의한 "탭 전환" 방식이 아니라 3개 그룹을 한 표에 나란히 보여주는 방식 |
| 기준연월 이력 조회 UI (6.8) | ✅ 구현됨(별도 "이력 조회" 페이지) |
| 프로모션 간 비교 | 🟡 부분 구현. "기준연월 간" 전사 합계 비교는 있지만, PRD가 정의한 "프로모션유형+시행월 단위" 비교(한 달 안의 여러 프로모션을 유형별로 나눠 비교)는 없음 |
| 프로모션 유형별 비교 | ⬜ 미구현. 이번 달 안에서의 지원유형별 소계표는 있지만, 여러 달치를 유형별로 모아 순위·평균을 비교하는 기능은 없음 |
| 차기 프로모션 설계안 제안 | ⬜ 미구현(의도적). PRD 3절 비목표가 "시스템이 자동 생성하지 않는다"고 명시하므로, 판단 근거(교차분석·문턱값 근접도·산점도·그룹 비교)까지만 제공하고 자동 추천은 만들지 않는 것이 맞다 — 5절과 3절이 서로 다르게 서술된 부분은 4절 "문서 정리"에서 다룬다 |
| 결과 내보내기/보고서 자동 생성 | ⬜ 미구현. 엑셀/PDF 다운로드 기능 없음 |

## 4. 문서 정리가 필요한 부분

- **PRD 5·6절의 단계 표기가 실제와 다르다**: 6.5~6.8절이 여전히 "최종 결과물"로 표기되어 있지만 실제로는 이미 구현되어 있다. PRD를 실제 구현에 맞춰 갱신할지, 아니면 "구현은 앞당겼지만 문서상 정식 완료 처리는 하지 않는다"로 둘지 결정이 필요하다.
- **3절 비목표("자동 설계안 생성 안 함")와 5절 최종 결과물("차기 설계안 제안")이 서로 모순**된다 — 어느 쪽이 맞는 서술인지 정리 필요.
- **데이터 모델(7절)이 실제 구현과 그레인이 다르다**: PRD는 SALES_RECORD를 "대리점×제품" 단위로 정의하지만, 실제 구현(`app/db.py`)은 "대리점" 단위다(제품 단위로 나눌 근거 데이터가 없었기 때문 — `.docs/13` 참고). PROMOTION_MASTER·STORE_AGM_BASELINE 테이블은 스키마만 있고 실제로 쓰이지 않는다(죽은 스키마) — 정리하거나 실제 용도로 재정의해야 한다.
- **10절 "남은 미해결 질문"에 이미 적혀 있는 것**: "프로모션 기준 마스터 업로드 + 산식 매칭 엔진"(6.2·6.3) 서술과 실제 워크북 인입 구현의 관계 정리가 아직 안 됐다. 지금은 실제로 워크북 안의 "프로모션 기준" 시트를 직접 읽는 방식으로 구현되어 있고, 이게 사실상 답이 된 상태라 이 질문은 "해결 완료"로 정리해도 될 것 같다.

## 5. 데이터 쪽에서 남은 것 (사용자 확인 필요)

- **전월매출·전년동월매출·매출증감율**: DC율 경로에서 아직 비어 있다. 사용자가 DC율 시트에 대리점별 매출로 추가할 예정이라고 확인함(`.docs/17`) — 추가되면 자동으로 인식하도록 이미 유연하게 구현해뒀다.
- **검증용 자료**: PRD 10절이 요청한 "담당자가 수기로 완성한 손익 보고서"(계산 로직 대조 검증용)가 아직 없다. 실제 계산값이 맞는지 교차검증하려면 필요하다.
- **8절 엣지 케이스 중 미구현**: 금액/비율 컬럼에 숫자로 변환 불가능한 값이 있을 때 "오류 행 목록"을 별도로 보여주는 기능, `전체` 제품군 조건과 특정 제품군 조건이 충돌할 때의 우선순위 처리(PRD도 "아직 실제 사례 없음"이라 명시) — 실제로 필요해지면 그때 구현.

## 6. 추가로 고도화 가능한 사항 (PRD엔 없지만 검토해볼 만한 것)

- **대리점 다중 선택 UI를 PRD 6.5.2 스펙에 맞추기**: 칩(chip) 목록 + "+ 비교 대리점 추가" 검색 패널 + 최대 5개 제한. 지금은 단순 멀티셀렉트라 대리점이 많아지면(현재 55개) 스크롤이 길어진다.
- **대리점 그룹별 조회를 탭 형태로**: 지금은 3그룹을 한 표에 다 보여주는데, PRD처럼 [전사 평균][우수][보통][저조] 탭으로 전환하면 한 번에 한 그룹에 집중해서 볼 수 있다.
- **결과 내보내기(엑셀/PDF)**: 팀장 보고용으로 화면을 그대로 캡처하지 않고 파일로 받고 싶을 수 있다.
- **프로모션 유형별/기간별 트렌드 비교**: 여러 달치가 쌓이면, "이 프로모션 유형이 지난 몇 달간 ROI가 어떻게 변했는지" 같은 시계열 비교가 가능해진다.
- **`promotion_master`·`store_agm_baseline` 죽은 스키마 정리**: 실제로 쓰지 않으므로 스키마에서 빼거나, 프로모션 기준 시트를 파싱한 결과를 여기에 저장하도록 재정의.
- **디자인 디테일**: 사이드바 로고는 반영했지만, 파비콘은 아직 Streamlit 기본이다. 대리점 다중 선택 UI를 design.md 컴포넌트 원칙(칩·카드)에 맞추면 더 CI에 부합한다.
