# 추가 화면(업로드·이력 대시보드) 설계 계획서

## 배경/동기
지금까지 `output/분석결과화면.html` 하나만 존재해, 실제 업무 흐름(① 실적·프로모션 기준 파일 업로드 → ② 분석 실행 → ③ 특정 기준연월 결과 확인 → ④ 여러 기준연월에 걸친 추이 파악)의 앞뒤 단계가 화면으로 표현되어 있지 않았다. 특히 `05_DBMS_도입_및_연월탐색_계획서.md`로 기준연월 이력 조회 기능을 반영한 뒤에는, "여러 기준연월의 결과를 한눈에 비교하는 추이 화면"이 자연스럽게 요구된다(PRD `02_PRD.md` 6.1·6.2절의 업로드 요구사항, 6.8절의 이력 조회 요구사항). 이 계획서는 화면 흐름을 3단계로 확장하기 위한 작업 범위를 정의한다.

## 범위
- `output/shared.css` 신설: 기존 `분석결과화면.html`의 `<style>`에서 페이지 공통 요소(브랜드 헤더, 기준연월 선택 UI, KPI 카드, 섹션 헤더, 배지, 안내 배너, 버튼, 푸터)를 분리해 새 화면들과 공유한다. `분석결과화면.html`은 이 파일을 `<link>`로 불러오고, 결과 표·비교 카드 등 자기 화면 전용 스타일만 남긴다.
- `output/01_실적업로드.html` 신설: PRD 6.1·6.2절 기반 업로드 화면(실적 파일 + 프로모션 기준 마스터, 개별/시트분리 업로드 모두 지원, 필수 컬럼 안내, 파싱 오류·기준연월 불일치 등 8절 엣지 케이스 일부를 화면 상태로 시연) → "분석 실행" 후 대시보드로 이동하는 동선.
- `output/02_이력_대시보드.html` 신설: 기준연월별로 DBMS에 누적 저장된 분석 결과를 한눈에 보는 화면. `dataviz` 스킬 절차(형태 선택 → 색상 배정 → `validate_palette.js` 검증 → 마크 규격 → 호버 → 접근성)를 따라 프로모션 시행별(기준연월별) 평균 본사영업이익율 추이, 매출증감율 추이(양/음 다이버징), 총 지원금액 추이(DC/프로모션 스택)를 인라인 SVG로 그린다. 기준연월 카드에서 "결과 보기"를 누르면 `분석결과화면.html?period=YYYY-MM`으로 이동.
- `output/분석결과화면.html` 소폭 수정: 상단에 "← 이력 대시보드" 내비게이션 추가, `?period=` 쿼리 파라미터로 진입 시 해당 연월을 자동 선택하도록 JS 보강.

## 방법
- 색상: design.md 2.5절 시맨틱 토큰과 2.2절 포인트 컬러(Green/Orange)만 사용. 차트 카테고리 색은 `dataviz` 스킬의 `validate_palette.js`로 사전 검증하며, design.md의 "ink→green→orange→gray-400" 순서를 문자 그대로 4색 마크에 적용하면 ink·gray는 채도가 낮아 색상 대비 기준을 통과하지 못함을 확인했다. 따라서 차트 마크(선·막대의 식별색)는 브랜드의 두 포인트 컬러(Green=긍정/성장, Orange=경고/음수)만 사용하고, ink·gray는 축·구분선 등 비식별 구조 요소로만 사용한다(검증 결과: Green+Orange 조합은 명도·채도·CVD 분리·대비 6개 기준 모두 통과).
- 차트는 라이브러리 없이 인라인 SVG로 직접 그리고(아티팩트가 아닌 순수 정적 HTML이므로 프로젝트에 이미 없는 차트 JS 의존성을 새로 들이지 않음), 각 지표를 단일 축·단일 형태의 소형 다중 차트(small multiples)로 분리해 "두 축 혼용" 안티패턴을 피한다.
- 업로드 화면은 실제 파일 업로드 로직 없이(백엔드 없음) 시연용 정적 상태(성공/경고/오류 상태 예시)를 보여주는 목업으로 작성한다.

## 완료 기준
- 세 화면(업로드 → 대시보드 → 상세결과)이 서로 링크로 연결되어 자연스러운 흐름을 이룬다.
- 대시보드의 차트 색상 조합이 `validate_palette.js` 검증을 통과한 조합만 사용한다.
- 세 화면 모두 design.md 토큰만 사용하고 임의 색상·간격을 새로 만들지 않는다.
