# PRD 작성 계획서

## 배경/동기
`02_프로모션효과분석_기획서.md`(프로젝트 루트)에는 문제 인식·페인포인트·분석 목적·성공 기준은 정리되어 있으나, 제품 요구사항 문서(PRD) 형식의 페르소나·사용자 스토리·기능 우선순위(MVP/v2)·데이터 모델·엣지 케이스가 별도로 명문화되어 있지 않다. 이를 PRD로 변환해 3일 PBL 개발 범위를 명확히 한다.

## 사용자 확인 사항 (사전 질의 결과)
- **타겟 사용자**: 실무 담당자(엑셀 업로드·분석 실행) + 팀장(결과 보고서를 보고 차기 프로모션 설계를 의사결정) — 2인 페르소나로 작성
- **MVP 범위**: 핵심 계산(DC율 반영 매출, 제품군 합산 판정, 지원금액 산출, 영업이익율·매출증감율 병렬 표시) + 단일 프로모션 결과 조회까지만 필수. 프로모션 간·유형 간 비교(기획서 7장 후반부)는 v2로 이연
- **기술 제약**: 기존 전제(Streamlit + pandas, stateless, 세션 간 데이터 미저장) 그대로 확정, 재검토 없음
- **완료(Done) 기준**: 기획서 9장의 성공 기준 문장을 PRD 성공 지표로 그대로 채택 (실적/기준 마스터 업로드 → 자동 산출·병렬 비교 → 집계 30분 이내 → 신규 프로모션 유형도 코드 수정 없이 분석)

## 범위
- 작성물: `02_PRD.md` (본 폴더 `.docs/` 하위)
- 포함 항목: 문제 정의 / 타겟 사용자·페르소나 2개 / 목표·비목표 / 사용자 스토리 / 기능 목록(MVP·v2·이후) / MVP 상세 기능 요구사항 / 데이터 모델 스케치 / 엣지 케이스·실패 상태 / 성공 지표 / 미해결 질문
- 제외: 화면 와이어프레임, 상세 아키텍처 다이어그램(별도 시스템아키텍처 문서 영역), 실제 코드 구현

## 방법
- `02_프로모션효과분석_기획서.md`와 프로젝트 루트 `.docs/`의 스키마·아키텍처 문서를 근거 자료로 사용해 임의 추정 없이 작성
- 기획서에 없는 내용(예: 구체적 UI 컴포넌트, 인증 방식)은 "미해결 질문"으로 명시하고 임의로 채우지 않음
- 문서는 한국어로 작성, Mermaid 다이어그램이 필요한 경우 Mermaid 형식 사용

## 완료 기준
- 위 10개 항목을 모두 포함한 `02_PRD.md`가 `.docs/`에 생성됨
- 기획서 내용과 모순되지 않고, 확인되지 않은 사실은 임의 생성 대신 미해결 질문으로 분리됨
